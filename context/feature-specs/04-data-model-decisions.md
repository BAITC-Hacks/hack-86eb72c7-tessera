# 04 — Принятые решения и передача участнику B

## Инструменты и инфраструктура

- Drizzle ORM 0.45.3 + node-postgres 8.23.0; Drizzle Kit 0.31.11. Отслеживаемые SQL-миграции в `drizzle/`, модель/репозитории в `lib/server/db/`. Миграции не запускаются автоматически при импорте модуля или сборке.
- Zod 4.6.5 для проверяемых DTO. Строгие объекты, русские безопасные ошибки, без неявного приведения чисел.
- AWS SDK v3 3.1138.0 для приватного Amazon S3. Целевое размещение PostgreSQL (AWS RDS) и S3 — `eu-central-1`; приложение получает действительные адреса/регион из серверных env. Аккаунты, bucket и платные ресурсы не создаются. На этом этапе разрешены только синтетические данные.
- Реальная PostgreSQL для интеграционных тестов: локальный временный кластер через `embedded-postgres` 18.4.0-beta.17, без Docker и без создания системных пользователей. Тестовый helper — только dev-зависимость. Совместимость managed RDS и закрытость реального S3 проверяются отдельно при выдаче доступов.
- Тесты: встроенный `node:test` + tsx 4.23.15, серверные импорты под `--conditions=react-server`. Next.js16 server-only граница обязательна.

## Числа, даты и приватность

- Количества, деньги и коэффициенты: PostgreSQL `numeric(30,8)`, JSON — каноническая десятичная строка. Максимум22 цифры целой части и8 дробной; лишняя точность отклоняется, не округляется. Нет экспоненты, NaN, Infinity, двоичного Number, `-0` и неканонических ведущих/замыкающих нулей. Отрицательное количество допустимо только там, где спецификация операции его допускает; цены/остатки/рекомендации неотрицательны.
- Календарные даты — ISO `YYYY-MM-DD`, месячные периоды — отдельная гранулярность, timestamps — UTC `timestamptz`. Часовой пояс бизнес-календаря будущего расчёта пока не выбирается.
- Manifest, числовой результат и опубликованные версии неизменяемы. Строки нормализованного снимка записываются callback нормализатора внутри транзакции публикации, до ready; после публикации запрещены также новые строки, даже до первого запуска. Review хранится отдельно. `canApprove` вычисляется, не принимается от клиента; diagnostic никогда не утверждается.
- Нормализованные схемы не принимают ФИО/телефоны/email и другие клиентские идентификаторы. Разрешён только явно обозначенный обезличенный ключ. Общие JSON-артефакты ограничены назначением/валидатором, а не произвольным payload.

## Закрытые объекты

- Максимальный размер одного объекта: 25MiB (26 214 400 байт), разрешены XLSX, CSV и ZIP для источников; отчёты JSON/CSV и экспорт CSV — отдельные назначения/префиксы.
- Срок подписанной операции: не более300 секунд. Ключи `projects/{projectId}/{sources|reports|exports}/{id}` генерирует сервер из валидных UUID проекта/объекта и назначения, не из имени файла; БД сохраняет тот же `id`. Произвольные ключи, traversal, публичные ACL и доступ к чужому проекту отклоняются.
- Загрузка ограничивается размером/типом/checksum. Подтверждение объекта сверяет SHA-256 и метаданные, не доверяет присланному пользователем checksum без проверки объекта. Повторная загрузка не должна незаметно перезаписывать принятый исходник.
- Политика хранения синтетической среды:30 дней, ручное контролируемое удаление после проверки ссылок. Автоматическое физическое удаление/жизненный цикл не реализуются в04. Для реальных данных партнёра требуется отдельное разрешение и политика; автоматически применять синтетические30 дней к ним нельзя.
- Bucket должен иметь Block Public Access и отключённые ACL (Bucket owner enforced). Адаптер проверяет закрытость либо требует подтверждённую конфигурацию; при невозможности проверки не выдаёт ссылку. Это не заменяет проверку реального AWS аккаунта.

## Граница A/B

A не реализует Clerk/Proxy/API-envelope, страницы, импортёр, фоновые задачи, прогноз и экспортный endpoint. Репозитории получают user ID только от доверенного серверного вызывающего кода и каждый раз проверяют владельца/архивирование. S3-адаптер требует серверный callback авторизации; B затем подключает `requireUserId()` из03. Эта точка подключения не объявляется выполненной до передачи03.

`package.json`, lock, `.env.example`, общие конфигурации остаются за B. Точный список пакетов для B — `scripts/data-model-dependencies.json`; ведущий временно устанавливает их с `--no-save --package-lock=false` для проверки. Переменные: DATABASE_URL, S3_BUCKET, S3_REGION, опционально S3_ENDPOINT/S3_FORCE_PATH_STYLE и стандартные серверные AWS credentials/роль. Реальные значения не включаются в Git. B добавляет зависимости и env-образец в своей ветке перед интеграцией.

## Итоговая граница модели

-25 предметных таблиц + служебный журнал `schema_migrations`; миграции применяет только явный checksum/advisory-lock runner. Drizzle metadata используется для генерации структурных изменений; триггеры проверяются/добавляются вручную в SQL. `drizzle-kit migrate` не является альтернативой этому журналу.
- `categoryIds` и ключи `safetyDaysByCategory` — исходные строковые ключи версионированных категорий, не UUID несуществующей таблицы Category. Пустой scope означает все значения; непустые ссылки проверяются внутри своего снимка.
- `numericFactors` — строгий массив числовых факторов, `dataQuality` — `complete/limited/unavailable`, `rationale` — безопасное русское объяснение. Ни одно из этих полей не принимает произвольные исходные продажи.
- Для каждого типа источника полнота указана явно. Предварительный full-gate проверяет продажи, остатки, путь, stockout, поставщиков, категории, рост, mapping и lead time; сезонность обязательна в provided-режиме. Отсутствие дополнительных monthly_sales/material_statement само по себе не блокирует full. Предметная достаточность M1–M4 проверяется алгоритмами07/08, не выдумывается в04; `queued/incomplete/[]` — ещё не оценённый запуск, не утверждаемый результат.
- Raw SQL-строки репозитория — внутренние snake_case записи. Перед API использовать явную проекцию, канонизацию numeric и UTC timestamp, затем строгую DTO-схему; прямой `RETURNING *` клиенту запрещён. Сквозная проверка сохранённых Project/SourceObject/Import/DatasetVersion/CalculationRun/DispatchIntent проходит через Drizzle camelCase и UTC-проекцию.

## Воспроизведение и передача B

1. B добавляет точные runtime/dev-зависимости из `scripts/data-model-dependencies.json` в package/lock своей ветки. Здесь package/lock не изменены, проверка выполнена локальной no-save установкой.
2. Для Linux-тестов embedded-postgres требуется postinstall пакета `@embedded-postgres/linux-x64@18.4.0-beta.17`: он восстанавливает14 относительных symlink внутри native-пакета. Если npm блокирует install scripts, B после проверки разрешает **этот пакет**, не все scripts, и выполняет его rebuild. Не использовать root/system-user/Docker обходы. В этой среде проверенный runtime установлен изолированно в `.omx/verification/postgres-runtime`; для тестов задан LD_LIBRARY_PATH на его native/lib. Этот путь — локальное доказательство, не требование deployment.
3. Команды после установки зависимостей:
   - `node --conditions=react-server --import tsx --test tests/contracts/*.test.ts tests/server/*.test.ts`
   - `npm run lint`; `npx next typegen`; `npx tsc --noEmit`; `npm run build`
   - `npx drizzle-kit generate` на текущем baseline не должен создавать миграцию.
   - `DATABASE_URL=... node --conditions=react-server --import tsx scripts/migrate-data-model.ts` — только явное развёртывание в выбранную БД; сборка не мигрирует.
4. B подключает проверенный Clerk user ID и серверные callback авторизации/поиска объекта. Реальный S3/RDS smoke-test, IAM/закрытость bucket и передача данных партнёра отдельно не выполнены. UI/API/импортёр/Trigger/прогноз не добавлены.
