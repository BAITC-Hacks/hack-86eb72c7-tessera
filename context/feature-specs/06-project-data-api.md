# 06 — API проектов и загрузки источников

## Цель

Защищённые API управления собственной рабочей областью и подготовки импорта. Парсер 05 существует; HTTP не запускает долгий расчёт. Основание: сценарий §3–5 и ограничения §9.

## Зависимости

03–05. Контракты ответов — `code-standards.md`. Транспорт загрузки — закрытая подписанная операция S3; конкретные ограничения срока/размера зафиксировать до реализации.

## Реализация и контракт

- `app/api/projects/route.ts`: `GET` возвращает собственные проекты с курсором, `POST {name}` создаёт проект с владельцем из сессии. Непустое имя после trim, проектный лимит 120 символов. Никакого поля доверенного `ownerUserId` в запросе.
- `app/api/projects/[projectId]/route.ts`: `GET`, `PATCH {name, archived?}`. Архивирование запрещает новые запуски/загрузки, не удаляет аудит.
- `app/api/projects/[projectId]/imports/route.ts`: `POST {fileName,size,contentType,checksum,sourceRole}` создаёт `Import` и ограниченную загрузку S3; `GET` возвращает список/состояния.
- `app/api/projects/[projectId]/imports/[importId]/finalize/route.ts`: `POST {manifest}` проверяет существование/размер и доверенный checksum средствами S3 HEAD/подтверждённых метаданных и сохраняет готовность к валидации. В 06 возвращает `status="awaiting-validation", validationPending=true`, но **не заявляет** выполнение фонового разбора. В 09a добавляется идемпотентная постановка `validate-import` и ответ `202`.
- `app/api/projects/[projectId]/imports/[importId]/route.ts`: `GET` возвращает `{data:{importId,status,stateVersion,datasetVersionId,report:{sources:[{sourceObjectId,sheets:[{sheetId,name,columns:[{columnId,label}],rowCount}]}],mappingIssues,counts,warnings},error}}`. Report до фоновой проверки может быть null. Листы/заголовки берутся из безопасного отчёта09a, не сырых клиентских предположений; значения строк клиентов/секреты не включать. Большой report выдавать ограниченными страницами с курсором, не подписанной публичной ссылкой.
- `app/api/projects/[projectId]/imports/[importId]/attempts/route.ts`: `POST {manifest}` создаёт новую попытку, переиспользуя только SourceObject исходного импорта того же проекта. Нельзя подменять произвольный ключ S3. Новый manifestHash — новый Import; совпавший checksum/manifestHash/версии по04 возвращает прежнюю попытку. До09a состояние uploaded и ответ201;09a добавляет атомарное freeze/dispatch с202. Старый manifest/результат не меняется. Этот путь не требует повторной загрузки bytes.
- `app/api/projects/[projectId]/datasets/route.ts`: `GET` — версии, источники/полнота/отчёт; подробные строки через ограниченную пагинацию, только если нужны экрану. Сырые закрытые файлы не раздаются без отдельной проверки доступа.
- `lib/server/projects.ts`, `lib/server/imports/service.ts`: авторизация/валидация/транзакции отдельно от HTTP. Ключ S3 строит сервер; чужой bucket/key/URL из клиента не принимается.

Первый manifest допускает явно unresolved сопоставление и заданную пользователем роль источника. Это разрешено для исследования заголовков в09a, но не для публикации DatasetVersion. `needs_mapping` + report образуют первый шаг; новая attempts с исправленным manifest — второй. HTTP не выполняет XLSX-preview самостоятельно.

Для всех API: `{data}` / `{error}`; `401` без сессии, `404` чужой ресурс, `409` конфликт/архив, `422` недопустимые поля. При повторе финализации — прежний импорт без дублей; checksum файла проверяется, не принимается на веру: если S3 не даёт доверенный checksum, проверку байтов выполняет задача09a до принятия набора. Скачивание целой книги внутри finalize запрещено. ETag multipart не считать checksum. Финализация фиксирует immutable manifest/hash; исправление создаёт новый Import по04. Учитывать лимиты частоты, CSRF и ограничение количества активных загрузок.

## Ограничения

Не добавлять совместный доступ, удаление исходников, UI, поставщиковые заказы или синхронный разбор крупных Excel в HTTP. Не выдавать подписанные ссылки на чужие объекты. Разрешение на загрузку не является разрешением на нормализацию персональных данных.

## Проверка готовности

- [ ] Два пользователя полностью изолированы по проектам, импортам и S3-ключам.
- [ ] Неверный размер/тип/checksum и произвольный путь отклоняются; прерванная загрузка не создаёт готовый набор.
- [ ] Повтор финализации не создаёт новый импорт; архивирование останавливает новые изменения.
- [ ] До 09a API честно сообщает ожидающую валидацию, а не успешный импорт.
- [ ] API-тесты, `npm run lint`, `npx tsc --noEmit`, `npm run build` проходят.
