# Прогноз регулярного спроса — 07

Чистый детерминированный модуль. Публичные функции экспортируются из `index.ts`:

- `forecastDemand: ForecastDemand` принимает неизменяемый снимок, scope и конфигурацию; возвращает `ForecastResult`.
- `sumDailyForecast(model, fromDate, toDateInclusive)` суммирует дневной прогноз по обеим включённым границам. Начало интервала не может предшествовать `model.startDate`.

Формула суммы соответствует `ForecastModelSchema`: календарная шкала учитывает фактическую длину месяца; `replace` отключает только будущий исторический тренд, `incremental` добавляет независимый внешний прирост. Исторический перенос базы не содержит внешний прирост. Округление до шага заказа здесь не выполняется.

## Данные и ограничения

- Даты вычисляются в UTC от переданного `asOfDate`, без чтения часов и случайности.
- Полная экспозиция дневных продаж берётся из сохранённого manifest05: `version.manifest[].importMetadata.sources[].period` и `periodCompleteness=complete`. Неизвестные дни не становятся нулевыми наблюдениями.
- `forecastBasis` сохранённого manifest разделяет транзакции и месячные агрегаты. Месячные факты не превращаются в выдуманные клиентские события.
- Возвраты/коррекции без согласованной политики дают недоступный прогноз, а не `abs(quantity)`. Несовместимые единицы не суммируются.
- Документы объединяются до поиска выбросов; дополнительная проверка клиентских недель обнаруживает дробление продаж по документам. Исключается только превышение baseline, перекрывающиеся исключения не вычитаются дважды.
- Stockout-интервалы объединяются как `[start,end)`. Восстановление использует сопоставимые доступные дни; отсутствие сравнений остаётся явным ограничением.
- Сезонность оценивается по полным годовым циклам. При нехватке истории используются подтверждённые индексы либо явно обозначенный несезонный режим.
- Месячный тренд требует устойчивости минимум в двух из трёх пар месяцев и явного ограничения категории. Короткая история, неподтверждённый внешний прирост и недостаточная полнота отражаются в предупреждениях/coverage.
- Для внешнего прироста обязательна `growthSemanticsByAssumption`: вид величины, месячный/годовой период, а для incremental — подтверждение независимого прироста. Неизвестная семантика блокирует полноту.
- Внутренние клиентские псевдонимы в доказательствах исключений нельзя передавать в OpenAI, Liveblocks или общий интерфейс.

## Проверка

`npm run test:forecast` запускает `node:test` с локальным resolve-hook для extensionless TypeScript imports. Тесты используют только синтетические DTO и проверяют результаты через `ForecastResultSchema`.

Сравнение с простым средним выводится в диагностике теста на синтетическом декабрьском holdout. Это измерение одного сценария, не доказательство промышленной точности или качества данных партнёра.

Модуль не выполняет закупочную оптимизацию, MOQ, сохранение, запуск фоновых задач или вызовы внешних моделей.
