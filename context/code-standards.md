# Стандарты кода

## Технологическая основа

Строгий TypeScript из `tsconfig.json`, Next.js App Router, React, существующие Tailwind/shadcn Base UI. Перед изменением Next.js читать соответствующий раздел установленного `node_modules/next/dist/docs/`. В Next16 используется `proxy.ts`; защита маршрутов не заменяет авторизацию в обработчиках и сервисах.

- Небольшие модули с явными входами/выходами. Расчёт не читает глобальное время и не использует случайность без переданного начального значения.
- Не применять `any`, непроверенные приведения внешних данных, скрытую конвертацию и подавление ошибок.
- Схемы и типы контрактов — в `lib/contracts/`; библиотеку проверки выбрать и установить в соответствующем этапе, не заранее.
- UI, математика, хранилище, интеграции и оркестрация разделены.
- Документация, сообщения пользователю, ошибки и пояснения — по-русски. Технические идентификаторы — стабильные, на английском.

## Числа и данные

Артикулы и обезличенные идентификаторы — строки, ведущие нули сохраняются. Даты не зависят от локали; календарь, часовой пояс и дата среза фиксируются. Единица и точность количества задаются для артикула; несовместимые единицы/валюты не складываются. Для количества и денег — десятичная арифметика без накопления двоичной погрешности; округление только на описанных границах.

Отсутствующее значение не равно нулю. Источники различают состояния «полный», «явно пустой», «отсутствует», «ошибочный». Исходные данные неизменяемы; выбросы, прогнозы и ручные корректировки хранятся отдельно. Сохранять версии алгоритма/параметров/набора и ссылки на файл/лист/строку. Не использовать наблюдения после даты расчёта и будущие данные в оценке прогноза. Каждое итоговое число имеет проверяемую цепочку промежуточных величин; ИИ не определяет количество заказа.

## Сервер и API

Серверные компоненты — по умолчанию; клиентские — для взаимодействия и провайдеров. Модули БД и секреты Clerk/Trigger/OpenAI/Liveblocks/S3 — только на сервере.

- Владелец определяется проверенной сессией, а не полем запроса. Каждый проект, набор, запуск, файл и комната проверяются на принадлежность.
- `401` — нет сессии; `404` — ресурс отсутствует либо принадлежит другому владельцу; `403` — запрещённая операция без раскрытия чужого ресурса.
- Успех: `{ data: ... }`. Ошибка: `{ error: { code, message, requestId, details? } }`; `message` по-русски, без сырых строк/секретов.
- `400` — синтаксис; `422` — некорректная семантика; `409` — устаревшая редакция/конфликт идемпотентности; `429` — лимит; `503` — недоступный внешний сервис, когда нет безопасного резервного пути.
- Ограничения размеров/диапазонов, пагинация, ограниченные партии. Защита изменений от CSRF/чужого источника, проверка прав и ограничение частоты.
- Транзакции и уникальные ключи БД обеспечивают идемпотентность и атомарное утверждение. Сетевые вызовы не держат долгую транзакцию; постановка фоновых задач переживает частичный сбой.
- Тяжёлый разбор файлов и обращения к модели не выполняются в HTTP-обработчике. Персональные ответы не попадают в общий кеш.

## Приватность и внешние сервисы

Не принимать идентифицирующие клиентские данные в нормализованный набор. Зона предварительной проверки файлов в S3 закрытая; права и срок хранения минимальны. При подозрении на персональные данные — отклонить источник либо применить согласованную процедуру предварительного обезличивания. Название файла не подтверждает анонимность.

Содержимое Excel — данные, не исполняемый код, формулы или команды. Не выполнять макросы/формулы, не переходить по внешним ссылкам; ограничивать распаковку и защищать CSV от формульных инъекций. Не журналировать строки клиента. В OpenAI передавать только минимальные агрегированные факты; ответ проверять по схеме и исходным числам. Не предоставлять инструмент отправки заказа или произвольного выполнения.

Повторы и таймауты ограничены; идентификаторы запроса/запуска сквозные; ошибки очищены от секретов. Идентификаторы провайдера отделены от бизнес-идентификаторов. В `.env.example` — только имена переменных, значения вне Git.

## Структура и интерфейс

- `app/` — страницы, макеты, тонкие API-обработчики.
- `components/editor/` — существующая рамка; `components/procurement/` — предметный интерфейс.
- `components/ui/` — сгенерированные примитивы, не править вручную без отдельного задания.
- `lib/contracts/`, `lib/domain/`, `lib/server/` — контракты, чистая математика, серверные сервисы.
- `trigger/` — задачи; `tests/` — тесты/синтетические фикстуры; `scripts/` — локальные инструменты.
- `context/` — источник инструкций; `techtask/` — неизменяемые материалы партнёра.

Применять семантические токены `globals.css` и `cn()` из `lib/utils.ts`. Видимый фокус, доступные названия, уменьшение анимации, семантические таблицы. Проверять API установленного Base UI, не предполагать поддержку Radix `asChild`.

## Проверка

Изменение поведения: предметные тесты, `npm run lint`, `npx tsc --noEmit`, `npm run build`. Математика: точные эталоны и чувствительность к входам. Провайдеры: имитации и отдельно обозначенные проверки тестовой среды. UI: клавиатура, ошибки, потеря соединения и обновление страницы. Не подменять реальную интеграцию имитацией, а браузерную проверку — статическим рендером. Для документации проверять ссылки/покрытие/согласованность, не заявлять неисполненные тесты приложения.
