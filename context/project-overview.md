# Tessera — рабочее место менеджера закупок

## Источник требований и текущее состояние

Основной источник: `techtask/TECHTASK.md`, кейс HACKALEM AI для ТОО «Электрокомплект» (ekt.kz), разделы 1–10. Tessera — рабочее название репозитория, не название из задания партнёра. Проектные решения ниже не следует выдавать за требования партнёра.

Пользователь выбрал Clerk, Trigger.dev, Liveblocks, OpenAI, PostgreSQL и S3. Интерфейс и документация — **только на русском**; имена файлов, API, переменных и стандартные технические идентификаторы не переводятся. Сейчас реализованы только библиотека UI и базовые компоненты панели/сайдбара; главная страница остаётся шаблоном Next.js. Серверная система ещё не реализована.

## Продукт и пользователь

Менеджер закупок рассчитывает регулярное пополнение склада, проверяет обоснования, корректирует количества и утверждает заказы, сгруппированные по поставщикам. Решение снижает трудоёмкость ручной консолидации Excel и помогает избежать дефицита/излишков, вызванных редкими расчётами и разовыми крупными продажами. «Проект» в интерфейсе означает изолированную рабочую область закупок. «Редактор» — табличное рабочее место, не графический холст.

## Цели

1. Проверяемо выполнить все пять обязательных требований на воспроизводимых синтетических наборах; материалы партнёра проверять только в пределах подтверждённого покрытия.
2. Показать числовую цепочку расчёта по каждому артикулу, складу и поставщику; текст ИИ не заменяет алгоритм.
3. Продемонстрировать путь: загрузка → проверка данных → расчёт → проверка менеджером → явное утверждение → скачивание.
4. Исключить идентифицирующие данные клиентов из расчётов, запросов к модели, журналов и событий совместной работы.

## Основной сценарий

1. Войти через Clerk; открыть или создать собственный проект.
2. Загрузить файлы партнёра либо явно обозначенные синтетические данные. Проверить сопоставление колонок и отчёт качества.
3. Выбрать склад/категорию, дату расчёта и явные параметры планирования; запустить версионированный расчёт.
4. Trigger.dev выполняет проверку, детерминированный прогноз и расчёт заказа, затем необязательное пояснение OpenAI. Liveblocks отображает этапы работы агентов; сохранённое состояние PostgreSQL остаётся главным.
5. Проверить группы поставщиков, срочность и аргументацию: сезонность, устойчивый рост, компенсацию отсутствия товара, исключённые разовые продажи.
6. При необходимости изменить количество с указанием причины и утвердить точную редакцию.
7. Скачать утверждённый заказ. Отправка поставщику в начальную версию не входит.

## Объём начальной версии

- Файловый импорт, неизменяемые версии данных, проекты одного владельца, явное сопоставление артикулов/поставщиков.
- Детерминированные количества; стандартное числовое объяснение доступно и при недоступности ИИ.
- Базовая срочность как поле выходного списка, без отдельного оптимизатора рисков.
- Clerk — доступ; Trigger.dev — фоновые задачи; Liveblocks — активность агентов; OpenAI — ограниченный этап объяснения.
- Таблица, ручная проверка, аудит утверждения, скачивание CSV как исходный проект формата до согласования 1С.
- Воспроизводимые синтетические данные с сезонностью, ростом, отсутствием товара и выбросами: разрешены разделом 6 задания, но не выдаются за реальные.

## За пределами начальной версии

Автоматическая отправка писем/заказов и запись в ERP; прямой коннектор 1С; переговоры с поставщиками; автономные покупки; произвольные инструменты агентов; организации/приглашения/совместное редактирование; биллинг; мобильное приложение. MOQ, кратность упаковки, условия поставщиков и графики категорий — опции раздела 8, не обязательные условия первой поставки. Метаданные MOQ сохраняются, но не влияют на расчёт без отдельного включённого правила. Нельзя обещать экономию или точность промышленного прогноза без измерений.

## Открытые вопросы и критерии успеха

Провайдеры PostgreSQL/S3, ORM, значения и семантика полей партнёра, недостающие данные, календарь/сроки поставки, единицы/округление, формат 1С, хранение/права передачи, модель/бюджет — в `progress-tracker.md`.

Успех: проверки M1–M5, изоляции владельцев и утверждения проходят; сбой ИИ/Liveblocks не портит числовой результат; экспорт соответствует утверждённой редакции; README воспроизводит демонстрацию. Проходят `npm run lint`, `npx tsc --noEmit`, предметные тесты и `npm run build`. Полноту данных партнёра и совместимость 1С подтверждают отдельно, не по скриншоту.
