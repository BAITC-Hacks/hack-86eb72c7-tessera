# Спецификации возможностей

Одна спецификация — одна ограниченная и проверяемая единица работы. Главный источник бизнес-требований — `../../techtask/TECHTASK.md`; архитектурные границы и фактический статус находятся в шести основных документах `context/`.

Начинать с [плана реализации](00-build-plan.md).01/02 — завершённая основа.03–15 и вставки09a/14a — предстоящая работа, не готовые функции. [Инвентаризация](../data-inventory.md) объясняет, какие поля реально есть и чего не хватает. Все документы и интерфейс — на русском; пути, API, типы и названия продуктов сохраняются.

## Содержание каждой спецификации

- **Цель:** что существует, какой результат нужен, что пока не делаем.
- **Зависимости:** завершённые этапы, решение по пакету/аккаунту, переменные окружения без секретов.
- **Реализация:** конкретные файлы, операции, контракты и состояния.
- **Правила:** входные проверки, владелец, идемпотентность, ошибки, приватность и числовая политика.
- **Ограничения:** соседние возможности, которые запрещено добавлять в этот этап.
- **Проверка готовности:** наблюдаемые тесты и применимые lint/typecheck/build, а не «всё работает».

## Процесс

1. Прочитать AGENTS.md, шесть файлов контекста и активную спецификацию целиком.
2. Проверить зависимости и открытые вопросы. Обозначить этап в трекере как начатый.
3. Реализовать только указанный объём. Мок не считать интеграцией, синтетику — данными партнёра.
4. Проверить критерии, права/ошибки/повторы, обновить доказательства и статус.
5. Не коммитить/публиковать автоматически: это отдельное указание пользователя.

## Имена и история

`NN-kebab-case.md`; номер совпадает с планом. Завершённые этапы не перенумеровывать: вставки используют суффикс (09a). Функциональный объём завершённой спецификации не переписывать; новое поведение — новый этап. Перевод исторического текста не означает изменения реализованного кода.

## Шаблоны

В `_templates/` сохранены русские шаблоны: универсальный, настройка, модель данных, сервер, интерфейс, подключение и инструкция генерации. Только **в шаблонах** допустимы незаполненные поля. Не копировать в активную спецификацию чужие примеры или утверждения о несуществующих файлах. Архитектура и реальные API имеют приоритет над формой шаблона.
