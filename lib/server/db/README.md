# PostgreSQL — этап 04

`schema.ts` описывает таблицы Drizzle; `drizzle/meta/` хранит базовый снимок для будущего `drizzle-kit generate`. Исполняемая миграция — `drizzle/0000_data_model.sql` с дополнительными триггерами неизменяемости и авторизации состояния. Применять **только явно** через `applyMigrations(pool)` или скрипт ведущего `DATABASE_URL=... node --conditions=react-server --import tsx scripts/migrate-data-model.ts`, а не через `drizzle-kit migrate`: его журнал не эквивалентен таблице `schema_migrations` и не заменяет SQL-триггеры. Повторный запуск `applyMigrations` проверяет SHA-256 файла; изменение уже применённой миграции требует новой миграции, а не правки истории.

`createRepositories(pool)` принимает `userId` от доверенного серверного слоя (Clerk здесь не реализован). Записи проверяют владельца и архив проекта; прямой SQL не является публичным интерфейсом. Метаданные и конфигурации проходят строгие контракты `lib/contracts/`, хеши связываются с каноническим JSON. Raw `RETURNING *` внутри репозитория — `snake_case`; API-DTO строятся на сервере из Drizzle `camelCase`/контрактов, без передачи сырых строк клиенту.

**Числа:** PostgreSQL `numeric(30,8)` округляет избыточную дробную точность до `CHECK`. Поэтому каждое будущее числовое поле импортёра должно пройти `DecimalStringSchema` до SQL; нельзя использовать JavaScript `number` или прямую запись непроверенных значений. `canonicalDecimal()` убирает только серверное нулевое дополнение при чтении, без двоичной арифметики. Для наблюдений/справочников отдельного универсального writer здесь намеренно нет.

Снимки данных/результатов неизменяемы: добавление строк набора после публикации запрещено, даже до первого запуска. `publishDatasetVersion(userId, input, writeSnapshot?)` вызывает доверенный серверный callback нормализатора06 в той же транзакции **до** статуса ready; callback получает PoolClient и ID снимка, пишет только заранее проверенные контракты, без сетевых вызовов. Ошибка откатывает строки, версию и ready вместе. Публикация требует проверенного импорта в состоянии `validating`; вернуть принятый импорт из ready обратно нельзя. Полный запуск проверяет обязательные источники; диагностический не утверждается. Закрытые S3-ключи/фактические SHA-256 проверяет адаптер хранения. `DispatchIntent` создаётся транзакционно, но отправка задач Trigger не входит в 04.
