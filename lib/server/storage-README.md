# Закрытое S3-хранилище — этап04

`createPrivateStorage` — серверный адаптер. Модуль импортирует `server-only`; его нельзя использовать из клиентского компонента. Вызывающий код создаёт `S3Client` с серверными `S3_REGION`, опциональными `S3_ENDPOINT`/`S3_FORCE_PATH_STYLE` и стандартными AWS credentials/ролью, а также передаёт `S3_BUCKET`. Секреты и значения переменных не включены в репозиторий.

## Контракт подключения

Обязательный `authorizeProject({userId, projectId, operation})` получает **уже проверенный** Clerk user ID от серверного вызывающего кода и возвращает `active`, `archived` либо `null`. Реализация должна проверять владение проектом в БД; адаптер не подменяет Clerk. `null` не раскрывает существование чужого проекта. Архив допускает только чтение; загрузка запрещена. Обязательный `resolveObject({userId, projectId, objectId})` читает сохранённые метаданные БД, не принимает ключ/путь от браузера. Адаптер повторно сверяет UUID, проект, назначение, форму ключа и S3 HEAD перед подписанием скачивания.

`upload` принимает байты на сервере (не неподписанную браузерную ссылку), размер 1–25MiB, точный MIME и SHA-256 в каноническом hex. Разрешены источники XLSX/CSV/ZIP, отчёты JSON/CSV, экспорт CSV. Имя файла не участвует в ключе. Ключ `projects/{projectId}/{sources|reports|exports}/{id}` с новым UUID; `PutObject` использует `IfNoneMatch: *`, явный `ChecksumSHA256` и серверные метаданные. После записи `HeadObject` с `ChecksumMode: ENABLED` подтверждает размер, MIME, SHA-256 и назначение. Метод `confirm` только повторно проверяет уже подтверждённый объект и требует действующего права записи; новая загрузка через него не выполняется. Только после успешной проверки возвращается `confirmed: true` для фиксации `SourceObject`/`ExportArtifact` в БД. `upload` возвращает серверный UUID `id`, который `createSourceObject` сохраняет без замены; `resolveObject` и `getDownloadUrl` используют тот же ID. Адаптер проверяет соответствие UUID в ключе ID записи. При передаче в репозиторий04 сопоставить `key → objectKey`, `sha256Hex → checksum`, `sizeBytes → byteSize`; при чтении из БД выполнить обратное сопоставление в `resolveObject`. Повторное содержимое с тем же SHA-256 следует искать в БД до загрузки: уникальность `(projectId, checksum)` не позволит записать новый ключ с тем же checksum и иначе оставит закрытый осиротевший объект. При ошибке фиксации возможен осиротевший закрытый объект; безопасная уборка и политика удаления — отдельная работа.

`getDownloadUrl` принимает только ID записи, проверяет сохранённый объект и выдаёт HTTPS-ссылку максимум на300секунд. Истёкшая ссылка должна запрашиваться заново; браузер не получает постоянный ключ. Проверка `GetPublicAccessBlock` требует все четыре флага, `GetBucketOwnershipControls` — `BucketOwnerEnforced`; отсутствие доступа к этим проверкам закрывает операцию. Bucket/IAM дополнительно должны запрещать публичное чтение и выдавать приложению минимальные права. Эта проверка не является доказательством реальной конфигурации AWS без учётных данных.

Серверная загрузка выбрана вместо presigned POST: так размер, MIME, хеш и условие запрета перезаписи проверяются до/при записи без периода действия повторно используемой браузерной подписи. Тяжёлый разбор XLSX/ZIP остаётся вне HTTP-обработчика. Адаптер не реализует маршрут загрузки, импортёр, автоматическое удаление или размещение облачных ресурсов.

## Проверка

`node --conditions=react-server --import tsx --test tests/server/storage.test.ts` использует подменённые команды S3/подпись и проверяет ограничения/отказы; живое подключение S3 не проверено. Интеграция с03/репозиторием04 требует явного handoff; оба callback обязаны быть реализованы только на сервере. До реальных данных партнёра необходимо согласовать права передачи, срок хранения и процедуру удаления.
