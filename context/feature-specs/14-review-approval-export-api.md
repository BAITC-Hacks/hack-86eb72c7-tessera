# 14 — Серверная проверка, утверждение и экспорт

## Цель

Сохранить корректировки менеджера и явное утверждение конкретной редакции. Скачивание не равно отправке поставщику. Основание: сценарий §3, выход §5, ограничения §9; зависимости 04, 06, 09. UI подключается в14a.

## Контракт

- `PATCH /api/runs/[runId]/recommendations`: `{reviewVersion, changes:[{recommendationId, reviewedQty, reason}]}`. Обновляет только review, атомарно увеличивает версию; ответ содержит новую версию/строки. `reviewedQty` — неотрицательная десятичная строка в единице SKU, без `NaN`/экспоненциальной строки и скрытого округления; сервер дополнительно проверяет допустимую точность и кратность минимальному шагу единицы SKU из неизменяемого снимка (нарушение —422); изменение требует непустой русской причины. Максимальная длина причины — проектный лимит 1000 символов.
- `GET /api/runs/[runId]/review`: версия, `snapshotHash` всего набора проверяемых строк, корректировки, актуальное утверждение, доступность экспорта. Контракт чтения рекомендаций09 включает актуальные review-значения либо однозначно связывает по ID.
- `POST /api/runs/[runId]/approve`: `{reviewVersion, expectedSnapshotHash, confirmed:true, idempotencyKey}`. Количество null/unavailable в исходном результате нельзя «исправить» review в полноценный результат: нужны новые входы/расчёт. Только владелец и только успешный, полный, проверяемый расчёт (`configuration.runMode=full`, `coverageGate=complete`, пустые `blockingReasons`, серверная повторная проверка `canApprove`; клиентскому флагу не доверять). В транзакции проверяются версия и хеш **полного набора строк**, не текущей страницы. Проверить наличие хотя бы одной положительной строки к заказу; пустой заказ не утверждать. Создать неизменяемый снимок Approval. Ключ и requestHash хранятся по04. Повтор того же ключа/тела возвращает тот же Approval; тот же ключ с другим телом (включая новую reviewVersion) —409. Другой ключ для той же уже утверждённой редакции не создаёт второй снимок.
- `GET /api/runs/[runId]/export?approvalId=...&format=csv`: только существующий актуальный утверждённый снимок своего запуска. Поток файла с безопасным Content-Disposition; не JSON. Ответ не создаёт и не изменяет Approval.

Нет сессии —401, чужой ресурс —404, ошибка количества/причины —422, неуспешный запуск/устаревшая версия/нет согласованного снимка —409. Ошибки по общему контракту, сообщения по-русски.

## Реализация

`lib/server/reviews.ts`, `approvals.ts`, `exports.ts` и тонкие `app/api/runs/[runId]/.../route.ts`. Схемы в `lib/contracts/review.ts`; транзакционные ограничения04. До экспорта менеджер сохраняет корректировки; отсутствие ручной правки означает исходное рекомендованное количество, не пустую строку.

После новой правки предыдущее утверждение остаётся в аудите, но не позволяет выгружать текущую редакцию. Первоначальный API отдаёт только актуальное утверждение; скачивание архивных снимков вне объёма. Гонка изменения и утверждения не утверждает смесь редакций. Частичный/ошибочный/отменённый расчёт не утверждается. Сбой необязательного объяснения OpenAI сам по себе не блокирует полный детерминированный расчёт.

## Формат выгрузки и согласование 1С

Предлагаемый демонстрационный формат: CSV UTF-8 с BOM, разделитель `;`, экранирование кавычками; русские заголовки `Поставщик;Артикул;Наименование;Склад;Количество;Единица;Срочность;Обоснование`. Десятичный разделитель и конкретная схема **должны быть согласованы** с конфигурацией 1С до заявления совместимости. Для синтетического демо фиксировать точку как технический десятичный разделитель и явно маркировать «Демонстрационный формат, не подтверждён для 1С».

Положительные утверждённые количества группируются по поставщику; нулевые строки не экспортируются. Не складывать разные единицы. Формульные префиксы `=`, `+`, `-`, `@` и управляющие символы в текстовых полях обезвреживаются без изменения артикула в БД; безопасная стратегия проверяется на целевом импорте. В файл не входят клиентские ID, исходные транзакции или секретные ссылки. Финальный формат/профиль преобразования имеет версию. Источник обоснования — проверенные факты/шаблон, не непроверенный ответ модели.

Экспорт формируется из неизменяемого Approval; сохранить метаданные/контрольную сумму и закрытый объект S3 идемпотентно. Для больших объёмов нужен отдельный ограниченный фоновый этап, не неограниченная генерация в GET; до реализации зафиксировать максимальный синхронный размер. Просмотренный файл не означает, что заказ отправлен/принят поставщиком.

## Ограничения

Без SMTP, мессенджеров, отправки поставщику, записи заказа в 1С, произвольных ролей и автоматического утверждения. Ни Trigger, ни OpenAI, ни Liveblocks не вызывают approve от имени человека.

## Проверка готовности

- [ ] Изменения проверяются сервером и аудируются; оригинальный расчёт неизменяем.
- [ ] Два конкурентных изменения/утверждения дают конфликт, не смешанный снимок; повтор запроса не дублирует Approval.
- [ ] Экспорт без текущего утверждения и попытка чужого пользователя запрещены; CSV совпадает с утверждёнными строками.
- [ ] Формулы/кавычки/переводы строк/ведущие нули/дробные единицы протестированы.
- [ ] Демонстрационный CSV не назван совместимым с1С без партнёрского теста; открытый вопрос отражён в трекере.
- [ ] Тесты API/гонок, `npm run lint`, `npx tsc --noEmit`, `npm run build` проходят.
