# 04 — Модель данных и закрытое хранилище

## Цель

После Clerk создать мигрируемую модель PostgreSQL и адаптер закрытого S3. Это фундамент, не готовые API или расчёты. Основание: задание §5–9, `architecture-context.md`, `data-inventory.md`. PostgreSQL/S3 подтверждены пользователем.

## Зависимости и решения

Зависимость: 03. До реализации выбрать ORM/миграции, провайдеры/регионы PostgreSQL и S3, срок хранения и лимиты файлов. Не устанавливать произвольную ORM молча. Секреты: `DATABASE_URL`, `S3_BUCKET`, `S3_REGION`, при необходимости `S3_ENDPOINT`, серверные учётные данные S3 либо роль среды; не `NEXT_PUBLIC_*`.

## Реализация

1. `lib/server/db/` — серверный клиент/репозитории; миграции в каталоге выбранного инструмента. `lib/server/storage.ts` — закрытые объекты и ограниченные подписанные операции.
2. `lib/contracts/datasets.ts`, `projects.ts`, `runs.ts`, `recommendations.ts` — проверяемые схемы. Количества/деньги в JSON — десятичные строки, в PostgreSQL — согласованный `numeric`; точность зависит от подтверждённых единиц.
3. Сущности:
   - `Project`: ID, `ownerUserId` Clerk, русское название, даты, архивирование; один владелец, без организаций.
   - `SourceObject`: проект, закрытый ключ S3, подтверждённый checksum, размер/тип; физический файл отделён от попытки нормализации. `Import`: проект, SourceObject, неизменяемый manifest/hash, версия схемы/адаптера, состояние `uploaded/awaiting-validation/validating/needs_mapping/invalid/ready/failed`, отчёт качества, `stateVersion`, `datasetVersionId`, timestamps/безопасная ошибка. Исправление manifest создаёт новый Import, не меняет принятый результат.
   - `DatasetVersion`: проект, неизменяемый manifest источников, дата среза, происхождение `partner/synthetic/mixed`, полнота каждого источника, версия схемы, ссылки импорта. Неполный набор не становится полным по умолчанию.
   - Справочники `Supplier`, `Warehouse`, `Product` и `ProductSupplier`: ключи источников, внутренний код/артикул, единица, категория, явные конверсии; MOQ и кратность — разные необязательные поля.
   - `MonthlySales` и `SeasonalityIndex`: период/гранулярность, единицы, полнота периода, происхождение/метод, версия набора. Месячный агрегат не преобразуется в продажу на один день. Все справочники Product/ProductSupplier/категории/конверсии также закреплены в снимке DatasetVersion: изменение текущего справочника не меняет старый запуск.
   - Версионированные `Sale`, `StockSnapshot`, `InboundShipment`, `StockoutInterval`, `CategoryPolicy`, `GrowthAssumption`, `SupplierLeadTime`: всегда связаны с набором. Продажа: дата, SKU/склад, количество, тип операции/ID события, необязательная цена и обезличенный клиент. Отсутствие клиента явно ограничивает M4.
   - `CalculationRun`: проект/набор, `requestedBy`, scope, дата среза, неизменяемая конфигурация/hash, версия алгоритма, ключ идемпотентности, ID Trigger, состояние `queued/running/succeeded/failed/cancelled`, этап `validate/forecast/recommend/explain` либо null до начала, timestamps, очищенная ошибка, монотонный `stateVersion`, `stageStates`, `explanationStatus=not_requested/pending/succeeded/degraded`.
   - Полнота результата: `coverageGate=complete/incomplete`, `blockingReasons`, вычисляемый сервером `canApprove`. Статус `succeeded` не означает полноту; `canApprove` требует `runMode=full` + succeeded + complete + отсутствие блокирующих ошибок и актуальную reviewVersion. `runMode=full/diagnostic` сохраняется в configuration: full отклоняет нехватку обязательных источников, diagnostic разрешает только явно ограниченную аналитику без утверждения.
   - `DispatchIntent`: тип операции `calculation/import`, business ID, payload hash, состояние доставки, число попыток, следующая попытка, lease, vendor ID; создаётся в одной транзакции с бизнес-записью. Восстановитель безопасно переотправляет недоставленное.
   - `Recommendation`: запуск, SKU/склад/поставщик, числовое обоснование, рекомендованное количество (nullable только для diagnostic unavailable), `quantityStatus`, единица, срочность, качество данных. Результат алгоритма неизменяем.
   - `RecommendationReview`: отдельное проверяемое количество/причина, автор, `reviewVersion`; редактирование не перезаписывает расчёт.
   - `Approval`: автор, точная редакция/хеш строк, время, `idempotencyKey` и `requestHash`; `ExportArtifact`: ссылка на утверждение, checksum, закрытый объект, формат/версия.
   - `RunEvent` и `AuditEvent`: безопасные структурированные события с порядковым номером; без содержимого исходных продаж.
4. Ключи уникальности: SourceObject `(projectId, checksum)`; импорт `(projectId, checksum, manifestHash, adapterVersion, schemaVersion)`; запуск `(projectId, idempotencyKey)` с проверкой hash запроса; рекомендация `(runId, productId, warehouseId, supplierId)`; утверждение `(runId, reviewVersion)` и независимо `(runId, idempotencyKey)` с requestHash; экспорт `(approvalId, formatVersion)`. Все связи проверяют принадлежность одному проекту, не только существование FK.
5. S3: разделить префиксы исходников/отчётов/экспорта. Ключи генерирует сервер, public ACL запрещены; имя файла не является путём. БД хранит метаданные, нормализованные строки и результаты; бинарные файлы — S3. Подписанная ссылка краткоживущая и выдаётся после авторизации.
6. Архивирование проекта блокирует новые изменения; физическое удаление/сроки хранения не внедрять без политики. Синтетические тестовые данные не смешивать с реальными без явного manifest.

## Ограничения

Не создавать страницы, импортёр, прогноз, Trigger-задачи или живое подключение 1С. Не использовать Liveblocks как финансовую БД. Не сохранять идентифицирующие клиентские данные в нормализованном наборе.

## Проверка готовности

- [ ] Миграции воспроизводятся на пустой тестовой PostgreSQL; ограничения FK/уникальности проверены.
- [ ] Чужой проект нельзя связать с набором/запуском, дубликаты не создают вторые записи.
- [ ] Изменения review не меняют исходное количество; числовые значения переживают запись/чтение без потери точности.
- [ ] S3 закрыт, произвольные ключи/публичный доступ запрещены; секреты отсутствуют в клиенте.
- [ ] Тесты репозиториев и `npm run lint`, `npx tsc --noEmit`, `npm run build` проходят.
