# API проектов и подготовки импорта

Сервисы принимают проверенный `userId` отдельным аргументом; клиент не назначает владельца. PostgreSQL хранит проекты, исходники и попытки. HTTP-обработчики не запускают разбор Excel, расчёт или Trigger.dev.

Финализация подтверждает закрытый объект через HEAD и фиксирует manifest. Ответ `awaiting-validation` с `validationPending: true` не означает, что данные проверены. Фоновая проверка относится к09a. Исправления manifest создают новую попытку, не изменяют предыдущую. До09a попытка возвращается в `uploaded` с HTTP201.

Предел загрузки —25MiB, срок подписанного PUT —300с. Настоящие S3/Clerk требуют отдельных интеграционных проверок; имитация хранилища в тесте их не заменяет. Ограничитель HTTP действует в одном процессе; это не распределённая защита.

## Проверки

```bash
NODE_OPTIONS=--conditions=react-server node --import tsx --test --test-concurrency=1 tests/project-data/*.test.ts
npx tsc --noEmit
npm run lint
npm run build
```

PostgreSQL-сценарии используют временный настоящий сервер из `tests/helpers/postgres.ts`. Не запускать несколько наборов PostgreSQL-тестов одновременно. HTTP-factory тесты проверяют границу сессии, Origin и безопасные ошибки без настоящего Clerk. Проверка браузера и живого AWS в эти тесты не входит.
