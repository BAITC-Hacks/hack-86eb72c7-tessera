# Расчёт пополнения — этап 08

Публичная точка входа: `calculateRecommendations` из `index.ts`, тип
`CalculateRecommendations` из неизменённого `lib/contracts/calculation.ts`.
Ядро не обращается к сети, БД, ИИ, текущему времени или случайным значениям.

## Методика и границы

- `StockSnapshot.quantity` трактуется как **свободный остаток**:
  `stockBasis="free_stock"`. Резерв повторно не вычитается. Это явное решение
  пользователя для реализации; подтверждение семантики партнёром остаётся открытым.
- Срез — конец `asOfDate`. Путь учитывается только в
  `(asOfDate, asOfDate + leadTimeDays + reviewPeriodDays]`; поступление будущего
  дня происходит перед спросом этого дня. Истёкшие, неизвестные и поздние ETA
  сохраняются в решениях по поставкам, но не уменьшают потребность.
- Входные DTO — нормализованные строки подтверждённого набора. Контракт поставки
  не содержит статуса отмены: отменённые/неподтверждённые документы должны быть
  обработаны до передачи ядру; восстановить такой статус из ETA нельзя.
- Категория задаёт период пересмотра и дни страховки. Дублирующие значения
  снимка запуска должны совпадать с политикой; неоднозначность блокирует расчёт,
  а не вводит скрытое значение по умолчанию. Lead time выбирается по специфичности:
  товар → категория → поставщик; конфликт одного уровня блокирует строку.
- `rawNeed = max(0, forecastDemandH + safetyStock - usableStock - eligibleInbound)`.
  Страховка — прогноз после горизонта. Положительное количество округляется
  вверх до подтверждённого шага; MOQ/кратность упаковки не применяются.
- Срочность определяется дневным балансом. Дефицит **до** первой возможной
  новой поставки имеет приоритет над итоговым количеством, включая нулевое.
  Нулевые строки сохраняются, единицы разных товаров не суммируются.
  Для согласованного округления баланс использует накопленный прогноз;
  временная симуляция имеет сложность O(H²), без заявления производительности
  на больших горизонтах и промышленных объёмах.
- Недостаточные факты дают недоступное количество или `issues`, а не ноль.
  Русское шаблонное обоснование не зависит от доступности ИИ.

## Связь с 07

Все обращения к сумме прогноза проходят через `forecast-sum.ts`.
Адаптер вызывает публичную `sumDailyForecast` из `lib/domain/forecast`
с четвёртым аргументом `"decimal"`; своей формулы в08 больше нет.
Модульные тестовые `ForecastResult` написаны вручную; отдельные интеграционные
тесты передают настоящий результат07 и проверяют обе выходные схемы.
Базовая фикстура плоская: сезонные индексы и тренд равны `"1"`, рост — `none`.
Отдельные проверки чувствительности изменяют только исследуемый фактор.
Количество и суммирование используют `bigint`; дробные степени коэффициентов
общего прогноза приближённо вычисляются через `Math.pow`, итог округляется
half-up до восьми десятичных знаков. Переполнение/исчезновение коэффициента из-за
машинного диапазона — явная ошибка, а не нулевой спрос.

Нейтральный эффективный режим07 при запрошенном внешнем росте допускается
только с неполным покрытием, запретом утверждения и соответствующим блокирующим
предупреждением того же SKU/склада либо глобального уровня. Такая строка остаётся
`unavailable`; остальные несогласованные режимы отклоняются.

## Проверка

`npm run test:replenishment` запускает `node:test` с локальным resolve-hook для
extensionless TypeScript-импортов. Проверки результата используют
`ReplenishmentResultSchema`. Для запуска нужны зависимости контрактов (`zod`)
и Node.js с `registerHooks`/поддержкой TypeScript type stripping.

| Критерий спецификации | Проверки |
| --- | --- |
| Точный эталон `100 + 20 − 30 − 40 = 50` | `core.test.mjs`: числовая цепочка и итог |
| Вклады M1, категория, рост и lead time | `core.test.mjs`: чувствительность на ненасыщенном наборе |
| Округление и законное насыщение нулём | `core.test.mjs`: дробный шаг, малое изменение, избыток |
| Границы ETA и urgent при rawNeed=0 | `edge.test.mjs`: шесть вариантов ETA и ранний дефицит |
| Поздние/неизвестные поставки, свободный остаток | `edge.test.mjs`: решения по партиям, отсутствие повторного резерва |
| Несовместимые единицы, поставщики, пропуски/отрицательные значения | `edge.test.mjs`: явное отклонение или недоступная строка/issue |
| Полные строки без ИИ | `core.test.mjs`: русский текст, количество, срочность, версии |
| Десятичная точность, календарь, детерминизм | `helpers.test.mjs` и `core.test.mjs` |

Исходные результаты проверки08 сохранены в подразделе «08» `context/progress-tracker.md`;
совместная приёмка — в подразделе «07» и `tests/domain/calculation/README.md`.
Эта таблица не объявляет сборку приложения успешной.
