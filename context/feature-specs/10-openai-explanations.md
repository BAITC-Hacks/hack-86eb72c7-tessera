# 10 — Проверяемые объяснения через OpenAI

## Цель

Готовые рекомендации уже содержат числовые факторы и детерминированный русский текст. Добавить необязательное улучшение объяснений через OpenAI Responses API, не передавая модели расчётную или управленческую власть.

**Статус:** запланировано, не реализовано. **Зависимость:** 09. OpenAI выбран пользователем, пакет/модель и аккаунт ещё не настроены.

## Условия начала

До внешних вызовов согласовать точный идентификатор модели с поддержкой нужной схемы, бюджет запуска, пределы токенов/размера партии, время ожидания, число попыток, регион/условия обработки и сроки хранения. `OPENAI_API_KEY` — только серверный секрет; модель задаётся серверной конфигурацией `OPENAI_MODEL`, не браузером. Версию пакета `openai` фиксировать после проверки текущей документации. Пока нет разрешения на реальные данные — только синтетические обезличенные примеры.

## Реализация

1. `lib/ai/explanation-context.ts`: формировать минимальный DTO из неизменяемой рекомендации: `runId`, `recommendationId`, `evidenceVersion`, список `{ factId, label, value, unit }`, детерминированный текст и разрешённые предупреждения. Факты включают вклад сезонности/тренда/прироста, stockout, исключённых выбросов, доступных остатков, учтённых поставок и сроки, но только в агрегированном виде.
2. Не отправлять книги, сделки, анонимные клиентские ID, контакты, ссылки S3, полные логи или ненужные цены. Названия/внешние строки считать недоверенными данными, не инструкциями; ограничить длину. Для MVP не давать модели инструменты, сеть, SQL или произвольные URL.
3. `lib/ai/explanation-schema.ts`: строгая выходная схема `{ explanations: [{ recommendationId, summary, evidenceRefs, warnings }] }`. `summary` — русский текст; `evidenceRefs` — непустой список разрешённых `factId`. `additionalProperties: false`; ограничения длины/числа строк применяются также после парсинга. Количество заказа/поставщик/утверждение отсутствуют как изменяемые поля.
4. `lib/ai/explain-recommendations.ts`: серверный Responses-вызов со структурой `text.format` типа `json_schema`, строгой схемой и `store: false`. Не путать с полем `response_format` из старых примеров Chat Completions. Использовать обычный запрос внутри Trigger, не второй фоновый оркестратор OpenAI.
5. `trigger/explain-recommendations.ts`: ограниченная дочерняя задача этапа `explain`, вход `{ runId, recommendationIds, promptVersion, schemaVersion }`. Проверить принадлежность строк запуску. Не повторять успешно сохранённый артефакт той же версии; новый текст никогда не заменяет исходные числовые результаты.
6. Проверять статус ответа, отказ, незавершённость, разбор схемы, ровно один результат для каждой ожидаемой строки, отсутствие чужих ID/ссылок и соответствие утверждений фактам. Любое новое числовое утверждение, не совпадающее с разрешёнными фактами в единицах и смысле, отклоняется. Если такую проверку нельзя надёжно автоматизировать, использовать только шаблонный текст с фиксированными числовыми подстановками, а не произвольную генерацию чисел.
7. Сохранить отдельно принятый артефакт, происхождение `ai | deterministic`, версии модели/промпта/схемы, длительность, расход токенов и безопасный код ошибки. UI всегда может показать исходный числовой разбор. Не сохранять полный промпт или скрытые рассуждения.

## Контракт результата и отказоустойчивость

- Расчётный результат из 08 неизменяем; ИИ-артефакт присоединяется по `recommendationId` и `evidenceVersion`.
- До запроса `explanationStatus: pending`; все приняты — `succeeded`; хотя бы один отказ/невалидный/просроченный ответ — `degraded` с шаблонным объяснением для затронутых строк.
- Нет ключа, исчерпан бюджет, `429`, сеть, отказ модели, неверная схема, галлюцинация ссылки или отмена — контролируемый резервный вариант; не потеря корректных рекомендаций.
- Повторы ограничены общим бюджетом, включая скрытые повторы SDK и задачи. Не допускать перемножения лимитов. Не утверждать, что идемпотентность БД исключает повторное списание за сетевой вызов после неопределённого тайм-аута.
- Пользовательское действие «пересчитать» не передаётся модели как команда. Помощник чата, если будет нужен, требует отдельной спецификации: разрешены только чтение и объяснение уже авторизованных фактов, не запись или запуск закупочных действий.

## Приватность

`store: false` уменьшает хранение состояния Responses, но не означает Zero Data Retention и не отменяет возможные журналы контроля злоупотреблений. Не заявлять ZDR без подтверждённых условий аккаунта. Нельзя отправлять реальные коммерческие данные до согласования внешней обработки; очистка локальной БД не доказывает удаление у поставщика.

## Ограничения объёма

Не выбирать формулы, не распознавать или исправлять исходные Excel-данные моделью, не добавлять RAG/векторную БД, чат, автономные циклы, LLM-инструменты изменения данных, утверждение или отправку поставщикам. Не делать OpenAI обязательным для выполнения must-have расчёта.

## Проверка готовности

- [ ] Строки численно идентичны при включённом/выключенном OpenAI; на русском доступен шаблонный резервный текст.
- [ ] Тесты охватывают валидный ответ, отказ, тайм-аут, незавершённый ответ, неверную схему, чужой ID, выдуманное доказательство/число и вредоносную строку источника.
- [ ] Ни ключ клиента, ни исходные продажи, ни секрет/ссылка S3 не попадают в запрос, лог или браузер.
- [ ] Соблюдаются лимиты времени/токенов/расходов и правила повторов; сбой ИИ не меняет `succeeded` расчёта.
- [ ] Проведён smoke-тест выбранной модели на синтетике; если аккаунт недоступен, это явно отмечено как непроверенное.
- [ ] Зафиксированы версия модели/SDK и решение о хранении; обновлён трекер.
- [ ] Проходят `npm run lint`, `npx tsc --noEmit`, `npm run build`.
