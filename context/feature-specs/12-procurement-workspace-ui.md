# 12 — Интерфейс рабочего пространства закупок

## Цель

Создать интерактивный интерфейс менеджера закупа на `/workspace` **только с демонстрационными данными**, переиспользуя готовую дизайн-систему и оболочку редактора. Менеджер проверяет готовность данных, задаёт область расчёта, запускает имитацию, изучает рекомендации по поставщикам, изменяет количества и явно подтверждает демонстрационное утверждение/предпросмотр экспорта. Реальные расчёты и сервисы в этом модуле не подключаются.

## Источники и решения

- `techtask/TECHTASK.md`, раздел 3: выбор → расчёт → проверка → корректировка → утверждение; раздел 5: таблица/дашборд с артикулом, поставщиком, количеством, обоснованием, срочностью и экспортом; раздел 7: группировка по поставщикам и пояснение каждой позиции; раздел 9: запрет неподтверждённой отправки и персональных данных клиентов.
- `context/ui-context.md` определяет токены и оформление. Русский язык интерфейса и документации подтверждён пользователем. Названия этапов, требование причины ручной правки и расположение контролов — проектные решения, а не дополнительные требования партнёра.
- В ТЗ нет графического холста или инструментов дизайна. Название «редактор» относится только к существующей переиспользуемой оболочке.
- Все фикстуры синтетические. Строки партнёрских файлов не включать в клиентский код и снимки экрана.

## Зависимости

- Завершённые модули: `01-design-system`, `02-editor`.
- Использовать существующие пакеты/примитивы; новые библиотеки интерфейса, графиков, ИИ, авторизации и реального времени в этом модуле не нужны.
- Модуль 13 подключает сохранённые проекты/расчёты через `/workspace?projectId=...`. Модуль14 отвечает за серверное утверждение/экспорт,14a — подключение этих действий. До их интеграции эти действия явно демонстрационные.

Мок не импортирует будущие контракты как зависимость 04, но заранее сохраняет их представление: количества — десятичные строки, статусы/этапы — перечисления 09. В 13 схемы переиспользуются из `lib/contracts/`, а JSON читается из `{ data }` / `{ error: { code, message, requestId, details? } }`, не как голый DTO. Нативный ответ токена Liveblocks — документированное исключение.

## Реализация

### 1. Маршрут и границы компонентов

Создать:

- `app/workspace/page.tsx`: серверную страницу, которая выводит клиентское пространство; метаданные страницы на русском. Корневую стартовую страницу в этом модуле не заменять.
- `components/procurement/procurement-workspace.tsx`: клиентский владелец состояний выбора, панели, имитации расчёта, проверки и диалогов.
- `components/procurement/project-selection.tsx`: локальный выбор/создание синтетической рабочей области и отдельную историю её запусков.
- `components/procurement/calculation-controls.tsx`: подписанную форму области расчёта и кнопку запуска.
- `components/procurement/data-readiness-panel.tsx`: состояния источников/импорта и сообщения проверки.
- `components/procurement/agent-progress.tsx`: этапы, состояние соединения и время обновления.
- `components/procurement/recommendation-table.tsx`: группировку по поставщикам, проверку строк, срочность и раскрытие.
- `components/procurement/recommendation-details.tsx`: числовые факты и пояснение.
- `components/procurement/order-review-dialog.tsx`: диалоги явного демонстрационного утверждения и предпросмотра экспорта.
- `lib/procurement/mock-workspace.ts`: типизированные синтетические фикстуры и сценарии, без серверных импортов/SDK. Типы здесь описывают представление, а не альтернативный доменный контракт сервера.

Если примитива нет, использовать семантические `table`, `select` и подписанные поля с существующими токенами. Не менять сгенерированные `components/ui/*` и не устанавливать табличный фреймворк.

### 2. Переиспользование оболочки

Скомпоновать `EditorNavbar` и `ProjectSidebar`, управляемые рабочим пространством. Сохранить плавающую панель без сдвига контента, анимацию, иконки переключения и `inert` закрытого содержимого.

Расширить `ProjectSidebar` необязательными `title`, `children`, `footer`, сохранив поведение для существующих вызовов. Общие подписи оболочки перевести на русский без изменения смысла: `Проекты`, `Мои проекты`, `Общие`, `Проектов пока нет`, `Общих проектов пока нет`, `Новый проект`; русские подписи открытия/закрытия панели:

- Если передан `children`, он заменяет прежние вкладки проектов.
- Если `footer` равен `undefined`, остаётся прежний нижний блок; `null` скрывает его; иначе выводится переданное содержимое.
- Пространство передаёт заголовок `Рабочие области`, два отдельных раздела `Проекты` и `История расчётов`, а в нижнем блоке — действующую локальную кнопку `Создать рабочую область (демо)`. Проект — рабочая область закупок с версиями наборов и запусками; не подменять список проектов историей запусков.
- Добавить необязательный `id`, чтобы имеющийся `sidebarId`/`aria-controls` верхней панели указывал на реальный элемент.
- Подписи доступности переключателя/закрытия и имя панели — на русском; поведение прежних вызовов сохраняется. В рабочем пространстве: `Открыть панель рабочих областей` / `Закрыть панель рабочих областей`. При необходимости передавать их необязательными свойствами.
- При закрытии кнопкой или Escape фокус возвращается переключателю. Панель немодальная: не ограничивать в ней фокус и не блокировать основной контент.

Правый блок верхней панели остаётся пустым. Заголовок и действия размещаются в основном содержимом ниже. Не переписывать завершённую спецификацию 02 под новые расширения.

### 3. Демонстрационные данные и сценарии

Фикстуры содержат два проекта с независимыми наборами данных и историями запусков. При выборе проекта показывать только его наборы/запуски; выбранный проект и выбранный запуск — разные состояния. Кнопка создания открывает существующий Dialog с обязательным названием, проверкой непустой строки после удаления краевых пробелов и лимитом 120 символов, отменой и `Создать в демо`. Создание только добавляет синтетический проект в память, выбирает его и показывает пустое состояние набора; предупреждение о демонстрации обязательно. Переименование/удаление/общий доступ не реализовывать. URL `projectId` станет авторитетным выбором после интеграции 13; в этой единице не выдавать локальный идентификатор за серверный.

Постоянно показывать `Демо · синтетические данные`. Добавить компактный подписанный выбор `Сценарий демо`, чтобы состояния воспроизводились без гонок таймеров и скрытых команд. Сценарии: готовность, нет набора данных, импорт, неверные данные, выполняется расчёт, успех, пополнение не требуется, ошибка расчёта, потеря связи/устаревание, недоступно ИИ-пояснение, отменённый запуск.

Фикстуры содержат:

- Двух поставщиков, не менее шести артикулов, два склада и две категории; правдоподобные кириллические названия и артикулы с ведущими нулями.
- Обычный спрос, сезонность, устойчивый рост, компенсацию отсутствия товара, исключённый разовый заказ обезличенного клиента, положительный объём в пути, предупреждение об отсутствии данных и нулевую потребность.
- Дату/версию источника и доступность фактов. Отсутствующая история stockout отличается от нуля подтверждённых периодов отсутствия; неизвестный объём в пути отличается от нуля.
- Исходную рекомендацию, отдельное изменяемое количество и допустимый шаг в виде канонических десятичных строк (например, `"12.5"`), единицу, обоснование, текст срочности, предупреждения и все поля расшифровки раздела 7.

При смене сценария с несохранёнными правками требовать подтверждение сброса. Перезагрузка страницы намеренно сбрасывает демонстрационные данные; постоянного хранения нет.

### 4. Готовность данных и импорт

Показывать название/версию/дату набора и отдельное состояние для каждого источника: история продаж, остатки, товары в пути, справочник товаров/категорий, поставщики/сроки поставки, сведения об отсутствии товара, прогноз прироста, материальная ведомость 1С/состояние сопоставления.

Состояния: `Готово`, `Не загружено`, `Проверяется`, `Требует проверки`, с пояснением. Не утверждать, что партнёр передал все источники. Настроенное допущение/резервный метод подписывается явно, а не изображается загруженным файлом.

`Выбрать файл (демо)` может открывать системный выбор файла и показывать только имя/размер в оперативной памяти. Не читать содержимое, не загружать, не сохранять и не определять схему настоящего файла. Показывать `Файл не загружается; результат проверки демонстрационный`. Отдельная кнопка `Показать проверку (демо)` выбирает готовый демонстрационный результат. Не признавать настоящий файл корректным/некорректным на основании имитации.

Ошибки привязаны к источнику, содержат число затронутых строк из фикстуры и действие восстановления. Кнопка расчёта заблокирована при нерешённых обязательных данных/блокирующих ошибках. Неблокирующие оговорки остаются видны при проверке заказа. Решение о готовности берётся из фикстуры; интерфейс не определяет производственную политику резервных расчётов.

### 5. Параметры и запуск расчёта

| Контрол | Подпись и поведение |
| --- | --- |
| Склад | `Склад`; обязательный выбор одного склада |
| Категория | `Категория`; все категории либо одна |
| История | `Период данных`; неизменяемый диапазон фикстуры |
| Дата среза | `Дата расчёта`; поле даты `asOfDate`, первоначально дата фикстуры; изменение помечает результат устаревшим, без реального пересчёта |
| Допущения | `Параметры расчёта`; неизменяемые горизонт покрытия и именованный прогноз прироста, с источником/меткой предлагаемого допущения |
| Запуск | `Рассчитать потребность`; до готовности заблокирован, причина видна рядом |

Нажатие запускает имитацию; повторный запуск блокируется до конечного состояния. Не реализовывать прогнозирование/формулы и редактирование настроек алгоритма. Для существующего результата показывать фактическую область/версию запуска. Изменённые фильтры помечать `Параметры изменены — требуется новый расчёт` и блокировать утверждение устаревшего результата. Сброс ручных правок при новом запуске/смене проекта, расчёта или набора — только после подтверждения.

### 6. Прогресс расчёта и агентов

Этапы и подписи соответствуют контракту 09: `validate` — `Проверка данных`, `forecast` — `Прогноз спроса`, `recommend` — `Расчёт заказа`, `explain` — `Подготовка обоснований`. `Готово` — итоговая подпись успешного запуска, не дополнительный этап. Это проектные подписи представления. Числовой детерминированный расчёт отделён от генерации текста; не создавать впечатление, что LLM принимает количественные решения.

Состояния запуска: `queued | running | succeeded | failed | cancelled`; отсутствие выбранного запуска — отдельное состояние интерфейса, а не статус `idle` API. Состояния этапа: `pending | running | succeeded | failed | skipped`; до начала `stage=null`. Объяснение: `not_requested | pending | succeeded | degraded`. Показывать русские подписи; пропущенный необязательный ИИ-этап не выглядит ошибкой расчёта. Отменённый запуск не допускает утверждение. Прогресс определяется этапами фикстуры, не выдуманным точным процентом. Допускается ограниченная имитация таймером с очисткой при размонтировании; каждое состояние также доступно явно через выбор сценария.

Ошибка содержит краткое объяснение и повтор, параметры сохраняются. Если числовой расчёт готов, а текст не получен, показывать `ИИ-обоснование недоступно — показан расчёт`, оставляя числовые факты доступными. При потере связи показывать `Связь потеряна — данные могут быть устаревшими`, время и заблокированные утверждение/экспорт. Повтор не создаёт второй одновременный запуск и не удаляет правки молча.

Будущая интеграция использует Trigger.dev и Liveblocks, но этот модуль не импортирует их SDK, не создаёт комнаты/задания/агентов/API/ключи. Не выводить инструкции модели, реальные клиентские идентификаторы и внутренние трассировки.

### 7. Рекомендации по поставщикам и расшифровка

Для каждого поставщика — семантическая таблица, заголовок и число строк. Не складывать количества с несовместимыми единицами. Добавить поиск по артикулу/названию и фильтр срочности; при отсутствии совпадений показать сброс фильтров.

Обязательные столбцы:

1. Артикул и название; исходная строка артикула сохранена.
2. Единица измерения.
3. `Рекомендовано`: неизменяемое расчётное количество.
4. `К заказу`: изменяемое проверяемое количество.
5. `Срочность`: текст фикстуры, без расчёта собственного рейтинга в интерфейсе.
6. `Обоснование`: краткие факты и кнопка `Подробнее`.
7. Состояние проверки/предупреждения и доступ к причине правки.

Раскрытие строки содержит подписанный список определений или небольшую таблицу фактов. Для каждого пункта — значение/единица либо явное `Нет данных`:

- Базовый регулярный спрос и использованный исторический период.
- Сезонный коэффициент/влияние и период.
- Устойчивый тренд и отдельно прогноз прироста, чтобы исключить скрытый двойной учёт.
- Дни/доказательства отсутствия товара и компенсированный упущенный спрос; наблюдённые и оценённые сведения различаются.
- Исключённый разовый/аномальный объём и причина исключения, включая обезличенную клиентскую агрегацию, когда применимо.
- Горизонт покрытия/срок поставки и целевая потребность.
- Текущий остаток и учитываемый объём в пути с временным горизонтом.
- Итоговая детерминированная рекомендация, округление/ограничения при наличии.

Отображать предоставленные факты: не пересчитывать формулы в браузере, не придумывать недостающие значения, не раскрывать клиента и не оставлять абзац ИИ единственным обоснованием. Различать сгенерированное и детерминированное объяснение. Пояснение есть у каждой строки, включая нулевую рекомендацию.

### 8. Ручная проверка, демонстрационное утверждение и экспорт

Локальные правки отделены от неизменяемого результата. Рекомендованное/проверяемое количество и шаг хранятся как канонические десятичные строки согласно 04/08. Черновой текст поля хранится отдельно, включая временно пустое/невалидное значение. Проверять конечное неотрицательное десятичное значение и допустимую точность/кратность шага без преобразования количества в двоичный `Number`; пустое поле — ошибка, не ноль. Допустить точку или одну десятичную запятую при ручном русском вводе, затем нормализовать в строку с точкой; экспоненциальную запись, разделители групп, `NaN`, `Infinity` и лишние символы отклонять. Ноль явно означает отказ от заказа позиции. Сохранять рекомендацию и требовать причину изменения. Ошибки показывать у полей и в доступной сводке. Сброс строки возвращает рекомендацию и очищает причину.

У каждого поставщика — явный флажок `Проверено`, по умолчанию снят. Любая правка его строк снимает флажок. Это предложенный локальный шаг проверки, не авторизация.

`Утвердить (демо)` открывает диалог только если расчёт завершён, актуален, соединение условно доступно, есть положительное количество к заказу, нет блокирующих ошибок данных/строк, причины правок заполнены и проверены все поставщики с положительными количествами. В диалоге — поставщики/число строк, единицы, изменения и неблокирующие предупреждения. Разные единицы в общее количество не суммировать.

Обязательный текст: `Это демонстрация. Заказ не сохраняется и не отправляется поставщику.` Только кнопка `Подтвердить в демо` создаёт локальное утверждённое состояние. Отмена/Escape не утверждают. Повторное подтверждение блокируется. Утверждённый снимок неизменяем; `Вернуться к проверке` отменяет локальное утверждение и возвращает редактирование.

Отдельный `Экспорт (демо)` доступен только для утверждённого снимка. Открывает предпросмотр: артикул, поставщик, проверенное количество, единица, срочность, обоснование. Подпись: `Предпросмотр — формат 1С не подтверждён`. Не создавать настоящий файл, не обращаться к API экспорта и не сообщать об отправке. Объяснить, что скачивание и утверждение с серверным аудитом подключаются в14a после модуля14. Кнопки отправки поставщику нет.

### 9. Оформление, доступность и адаптивность

Следовать `context/ui-context.md`: токены, типографика, скругления, адаптивность. Управление/статусы — компактные панели, рекомендации — таблицы, не сетка огромных карточек показателей.

Все видимые и доступные подписи нового маршрута — на русском. Модуль03 устанавливает глобальный `lang="ru"`. Если независимый макет12 выполняется раньше03, пометить своё русское содержимое `lang="ru"`; глобальную локализацию не считать уже выполненной. Форматировать числа/даты через `Intl` на границе отображения без потери точности десятичных строк; не приводить значения API к `Number` ради форматирования. Черновой ввод не является локализованным значением хранения. Проверить кириллицу и длинные названия.

- Семантические заголовки, подписи формы, заголовки/описания таблиц и связи раскрытия.
- Краткий прогресс объявляется через `role="status"`/вежливые уведомления, не по каждой ячейке; ошибки — соответствующим уведомлением.
- Видимый фокус, подписанные области прокрутки таблиц с клавиатуры, текстовые подписи статусов/иконок.
- Существующий Dialog для подтверждения, доступных ошибок, управления фокусом, закрытия и возврата фокуса.
- Проверки ширин 320px, 768px, 1440px, масштаба 200% и уменьшенного движения. Горизонтальная прокрутка допустима внутри подписанной таблицы, не у всей страницы.

## Ограничения объёма

- Не создавать серверные маршруты, схему/миграции, хранилище, реальный разбор импорта, нормализацию, прогноз/формулы заказа и загрузку партнёрских данных.
- Не подключать Clerk, OpenAI, Trigger.dev, Liveblocks; никаких секретов/производственных запросов. Защита маршрутов принадлежит спецификациям авторизации/интеграции. Не удалять и не обходить уже реализованную защиту маршрута.
- Никаких реальных утверждений, скачиваний, отправки поставщику, заявлений о совместимости 1С и хранения в localStorage.
- Не создавать чат-пространство, графический холст, обязательные графики трендов, оптимизацию MOQ, совместное редактирование, реальный CRUD проектов и переключатель тем. Допускаются только описанные локальные создание/выбор демонстрационного проекта.
- Завершённые спецификации 01/02 и сгенерированные UI-примитивы не менять. Оболочку расширять только описанными свойствами, сохраняя поведение прежних вызовов.

## Критерии готовности

- [ ] `/workspace` показывает демонстрационную метку, оболочку, параметры, готовность, прогресс и таблицы по поставщикам; производственных запросов нет.
- [ ] Все сценарии доступны: загрузка, неверные данные, ошибка, нет набора, нет совпадений, нулевая потребность, нет ИИ-пояснения, потеря связи — разные состояния.
- [ ] Создание/выбор проекта работает только в памяти; история запусков показана отдельно и ограничена выбранным проектом; отмена диалога не создаёт проект.
- [ ] Два поставщика/шесть синтетических артикулов покрывают перечисленные случаи; все поля расшифровки и пояснения доступны без персональных сведений.
- [ ] Изменение параметров помечает результат устаревшим; переключение/перезапуск с правками требует подтверждение; двойное нажатие не создаёт параллельные имитации.
- [ ] Отрицательные, нечисловые, пустые и слишком точные количества/отсутствие причины блокируют утверждение; ноль явно обработан; правки отменяют проверку/утверждение.
- [ ] Утверждение требует явной кнопки в диалоге; отмена/Escape не утверждают; экспорт использует утверждённый снимок и не скачивает/отправляет заказ.
- [ ] Разные единицы не складываются; неизвестное не заменяется нулём; рекомендованное и проверенное количество различаются.
- [ ] Прежние вызовы боковой панели работают, контент не сдвигается, закрытая панель `inert`, связи контролов/возврат фокуса исправны.
- [ ] Браузерная проверка охватывает клавиатуру, диалоги/фокус, малый экран/прокрутку, длинную кириллицу, масштаб 200%, уменьшенное движение, контраст, консоль; результаты или ограничения записаны.
- [ ] Добавлены компонентные/интеракционные тесты в принятом проектом наборе инструментов: валидация количества, устаревание при смене области, отмена проверки поставщика, условия утверждения, исключительно демонстрационный экспорт. Если инструмента ещё нет, выбор/установка фиксируются явно до реализации тестов; непроведённые проверки не объявляются успешными.
- [ ] `context/progress-tracker.md` отражает фактический объём и проверки; завершение модуля 12 не означает готовность серверной интеграции.
- [ ] Успешны `npm run lint`, `npx tsc --noEmit`, `npm run build`.
