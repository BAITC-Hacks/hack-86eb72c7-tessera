# 05 — Проверяемый импорт данных

## Цель

Получить неизменяемый нормализованный набор с происхождением каждой строки и отчётом качества. Обязательные входы задания §5–7 не игнорируются. Особенности всех 12 XLSX перечислены в `../data-inventory.md`.

## Зависимости

03, 04. Сначала выбрать поддерживаемую библиотеку XLSX и лимиты размеров/распаковки по измерениям приложенных архивов; не обещать приём архива, который превышает лимит. Длинный разбор оформляется чистым сервисом/локальным CLI, запуск из HTTP подключается через Trigger в 09a. HTTP в этом этапе не выполняет тяжёлый импорт.

## Реализация

1. `lib/contracts/imports.ts`, `lib/server/imports/`, `scripts/import-dataset.ts`: схемы manifest, безопасный парсер и адаптеры IEK/Systeme. Тесты используют синтетические файлы и редактированные безопасные фрагменты, не копируют закрытые данные в публичный Git.
2. Каждый источник имеет роль: `sales`, `monthly_sales`, `stock`, `inbound`, `stockouts`, `suppliers`, `categories`, `growth`, `seasonality`, `product_mapping`, `material_statement`. Manifest фиксирует файл, лист, версию, дату выгрузки, период, единицы, полноту, сопоставление колонок, приоритет и причину ручной коррекции.
3. Схемы продаж/остатков/пути/справочников следуют 04. Для документов различать факт отгрузки, возврат и заказ; отрицательные количества не превращать в положительные. До согласования документа/знака строка `unresolved`, не «продажа». Месячные агрегаты не складывать с теми же транзакциями; выбирается одна база прогноза, другая сверяет суммы.
4. Коды строковые, ключ источника входит в пространство имён. Сопоставление SKU/поставщика/склада и конверсии явные. Заголовки дат IEK преобразуются в отдельные поставки; дата ETA не заменяет норматив срока поставки.
5. `t=e`, `#N/A`, пустые кеши, пропуски и нули различаются. Не исполнять формулы/макросы/внешние ссылки. Заголовки, подытоги и итоговые строки не становятся продажами. Дубли сезонных листов обнаруживаются по происхождению/хешу.
6. Для stockouts принимать явные `[startDate,endDate)` интервалы с источником; месячный нулевой остаток не генерирует интервал. Категория/рост/сезонность с неизвестной семантикой остаются неразрешёнными. `Заказ` в Excel — не утверждение. MOQ не равно кратности. `СС реал` не считать ценой без подтверждения.
7. Проверять потенциальные идентификаторы клиентов до принятия нормализованных данных. Отсутствие ID — `customerAnomalyCoverage=unavailable`, не замена номером документа. Отчёт анонимности — проверка по утверждённой политике, не обещание абсолютной анонимности.
8. Отчёт: строки всего/приняты/отклонены/неразрешены, дата/единицы, ошибки по файлу/листу/строке, конфликты, покрытие каждого обязательного источника и M1–M4. `ready` означает корректно принятый набор, а не достаточность для любого алгоритма: запуск отдельно проверяет доступность обязательных входов.
9. Повтор checksum+manifestHash+adapterVersion+schemaVersion в одном проекте возвращает прежний результат. Физический SourceObject дедуплицируется отдельно по checksum; новое сопоставление того же файла создаёт новый Import. Не изменять ранее принятый набор; исправление создаёт новую версию. Синтетический генератор покрывает все отсутствующие входы и маркирует происхождение. Сырые конфиденциальные данные не отправлять внешним моделям.

10. Перекрывающиеся выгрузки с разными checksum сверять по подтверждённому ключу операции/строки источника. Если line ID отсутствует, не схлопывать одинаковые законные строки автоматически: выбрать неперекрывающиеся источники/периоды или потребовать ручное разрешение конфликта.
11. Полнота источника: `complete`, `explicit_none`, `missing`, `invalid`. Подтверждённое отсутствие пути/stockout/внешнего прироста допустимо как `explicit_none`, непереданный файл — `missing`. Подтверждение сохраняет автора/основание; не означает, что неизвестный факт стал нулём. На месячной базе без транзакций дневные/клиентские проверки помечаются недоступными.

## Контракт сервиса

`validateImport(manifest, objects) -> {status, report, normalizedDraft}`; `commitDataset(validatedDraft) -> DatasetVersion`. Ошибки не приводят к частично видимому набору. Неизвестный источник — диагностируемая ошибка, а не молчаливый пропуск.

## Ограничения

Без UI, фоновой оркестрации, прогнозов и исправления исходных файлов. Данные из S3 загружаются только по серверному ключу в разрешённом префиксе; произвольные URL запрещены.

## Проверка готовности

- [ ] Фикстуры всех форматов проходят либо дают точную диагностическую причину отказа.
- [ ] Ошибки Excel не становятся нулями; отрицательные значения, смешанные единицы, ведущие нули и частичный сентябрь сохраняют смысл.
- [ ] Повторный импорт идемпотентен; транзакции и месячные суммы не удваивают спрос.
- [ ] Отсутствующие клиентские ID/stockouts/lead time явно видны и ограничивают расчёт.
- [ ] Есть проверки больших/вредоносных архивов, формул, имён путей и частичного сбоя.
- [ ] Тесты, `npm run lint`, `npx tsc --noEmit`, `npm run build` проходят.
