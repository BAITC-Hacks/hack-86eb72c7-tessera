# Проверяемый импорт — этап 05

Модули доступны только серверу. HTTP, Trigger, расчёт потребности и интерфейс сюда не входят. Данные XLSX не исполняются; формулы, ошибки и неподтверждённая семантика дают диагностику, а не ноль. `ready` означает принятую структуру, не готовность всех обязательных входов будущего расчёта.

## Локальная синтетическая проверка

Зависимости передаются владельцу package/lock в `scripts/data-import-dependencies.json` вместе с зависимостями 04. Установка no-save текущей рабочей копии не означает воспроизводимую установку чистого checkout до принятия этой передачи.

```bash
node --conditions=react-server --import tsx scripts/generate-import-fixture.ts /tmp/tessera-synthetic-new
node --conditions=react-server --import tsx scripts/import-dataset.ts \
  --manifest /tmp/tessera-synthetic-new/manifest.json \
  20000000-0000-4000-8000-000000000001=/tmp/tessera-synthetic-new/synthetic.xlsx
node --conditions=react-server --import tsx --test --test-concurrency=1 tests/imports/*.test.mjs tests/imports/*.test.ts
```

Каталог должен быть новым либо не содержать `synthetic.xlsx`/`manifest.json`: генератор не перезаписывает существующие файлы. Создаются 12 ролей источников, строковый SKU `000123`, продажи с отдельным крупным заказом и вымышленными `anon_*`, месячная история роста, сезонные индексы, явный интервал отсутствия товара, остаток 0, путь, сроки, категории, сопоставление и материальная ведомость. Значения вымышлены и воспроизводимы; SHA-256 вычисляется для фактических байтов XLSX, бинарная идентичность ZIP между запусками не обещается. Это фикстура импорта, не доказательство точности прогноза или полноты данных партнёра.

CLI — **только dry-run**: проверяет локальные файлы и печатает статус/отчёт, не сырой черновик. Не подключается к БД/S3, не создаёт проект и не публикует набор. Код выхода: `0` — ready, `2` — invalid/needs_mapping, `1` — некорректный ввод/ошибка чтения/парсера. manifest ограничен 1MiB, каждый файл — 25MiB до чтения, URL не принимаются. Один `UUID=путь` передаётся для каждого уникального complete-объекта. Отсутствующий источник не заменяется пустым файлом.

## Серверная граница

`validateImport(manifest, objects)` принимает только уже авторизованные сервером байты `{id,bytes}` и возвращает `{status,report,normalizedDraft}`. Внешний слой обязан проверить владельца и получить объект по разрешённому приватному ключу S3; передавать произвольные URL нельзя. Ошибки manifest/checksum/формата возвращают invalid и безопасный диагностический код. Состояния `missing` и `explicit_none` различаются, последнее требует автора и основания. Месячная и транзакционная история сохраняются отдельно; manifest явно выбирает базу прогноза.

`commitDataset` публикует только неизменённый черновик, прошедший проверку в этом процессе. Используется доверенная серверная личность, не ID пользователя из HTTP-тела. По умолчанию сервис записывает поддерживаемые предметные строки и связи в одной транзакции. Необязательный `writeSnapshot` предназначен для доверенного расширения и тестирования отказа; тест callback не доказывает работу основного writer. Материальная ведомость пока не имеет согласованной таблицы: публикация такого черновика отклоняется, а не молча теряет строки. CLI остаётся dry-run.

## Ограничения и доказательства

- Консервативные лимиты парсера задаются в `parser.ts`; 25MiB входа не обещает приём любых книг такого размера, лимиты распаковки/листов/строк также обязательны.
- Архивы партнёра в этой рабочей копии отсутствуют. Нельзя заявлять проверку всех 12 реальных XLSX, размеров и бизнес-семантики партнёра по синтетике.
- Реальные клиентские данные не включены; `anon_*` не доказывает согласованную анонимизацию реальных источников. Отчёт не должен содержать исходные значения клиента.
- Синтетический end-to-end проверяет XLSX → парсер → адаптер → сервис/CLI. PostgreSQL/S3/Clerk и HTTP не подменяются этим тестом; доказательства их проверки фиксируются отдельно.

Не завершены числовая сверка месячных/транзакционных сумм, полный путь конверсий единиц и разрешение приоритетных конфликтов; вторичная история пока только отмечается для сверки. Спецификация05 остаётся в работе.
