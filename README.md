# Tessera

Проект хакатона HACKALEM AI: расчёт рекомендуемых заказов для пополнения склада ТОО «Электрокомплект».

Объединены основа авторизации Clerk, светлое демонстрационное рабочее место B и модель данных04 от A: PostgreSQL/Drizzle, миграции, проверяемые контракты и приватный S3-адаптер. Экран использует синтетические данные и хранит правки только в памяти страницы. HTTP API, импортёр, расчётное ядро и подключение реальных данных/экспорта ещё разрабатываются.

- Исходное задание: `techtask/TECHTASK.md`.
- Инструкции: `AGENTS.md` и шесть документов `context/`.
- План: `context/feature-specs/00-build-plan.md`.
- Исследование файлов: `context/data-inventory.md`.
- Статус и открытые вопросы: `context/progress-tracker.md`.

Выбраны PostgreSQL, приватное S3, Clerk, Trigger.dev, OpenAI, NVIDIA и Liveblocks. Интерфейс и документация — на русском. Инструкции настройки сервисов, методология и воспроизводимая демонстрация дополняются при реализации соответствующих этапов.

## Локальный запуск демо

1. Установить зависимости: `npm ci`.
2. Если `.env.local` ещё нет, создать его из `.env.example`. Существующий файл с ключами не перезаписывать. Для демонстрационного экрана ключи не нужны; без Clerk экран входа сообщает о недоступности, API возвращает503.
3. Запустить `npm run dev` и открыть `http://localhost:3000/workspace`.
4. Проверить две группы поставщиков, раскрыть обоснование, изменить количество и указать причину. Отметить поставщиков проверенными, открыть диалог утверждения и явно подтвердить. «Экспорт (демо)» показывает предпросмотр; заказ не сохраняется и не отправляется. Обновление страницы сбрасывает демо-правки.

Проверки: `npm run test:auth`, `npm run test:workspace`, `npm run test:ai`, `npm run test:realtime`, `npm run test:client`, `npm run test:data-model`, `npm run lint`, `npx tsc --noEmit`. На объединённом дереве выполнены66 тестов, lint, TypeScript и `npx next build --webpack` на Node24.19.0/macOS arm64. Тестовый загрузчик использует современные Node API; другие версии проверяются отдельно. Стандартный `npm run build` использует Turbopack, чья проверка в текущем окружении ранее была ограничена запуском процессов/портов. Это не подтверждение развёрнутого сервера или живых внешних интеграций.

`test:data-model` создаёт временный локальный PostgreSQL на свободном loopback-порту, выполняет миграции только в нём и очищает его после проверки. Нужен разрешённый запуск локального процесса/порта; Docker и `DATABASE_URL` реальной среды не используются. Для выбранной рабочей БД миграция запускается только отдельной явной командой из [инструкции04](context/feature-specs/04-data-model-decisions.md), никогда при сборке.

После установки зависимостей аудит показал4 moderate замечания в цепочке dev-инструмента Drizzle Kit/esbuild, без high/critical. Автоматическое предложение откатить Drizzle Kit на несовместимую версию не применено; обновление требует отдельной совместимой проверки.

Ключи серверных провайдеров заполняются только в локальном окружении; `.env.local` исключён из Git. OpenAI и NVIDIA получают только разрешённые агрегированные факты после подключения соответствующих этапов, их отказы не должны менять рассчитанные количества. Контракты передачи и непроверенные интеграции: [context/b-handoff.md](context/b-handoff.md).

Документы `context/` отслеживаются в Git. Исходные архивы партнёра, локальные заметки/harness и браузерные артефакты в публикацию не включаются. Совместимость экспорта с реальной 1С ещё не подтверждена.
