# Дополнение B: обязательные OpenAI и NVIDIA

Пользователь 23.09.2026 потребовал осмысленно использовать оба API и указал по $50 доступного кредита у каждого. Это дополнение к исходной архитектуре; наличие действующих ключей, моделей и баланса ещё не проверено. Расходы API отделены от лимитов Codex.

Текущее ограничение: пользователь сообщил о добавлении ключа OpenAI, но запретил пока его использовать. До отдельного разрешения реальные запросы, smoke-тесты и проверки аккаунта OpenAI не выполняются; локальные проверки используют имитацию ответов.

- OpenAI: объяснения отдельных рекомендаций по спецификации10, с проверенными ссылками на факты и детерминированным резервным текстом.
- NVIDIA: сводка того, на что менеджеру обратить внимание при проверке группы поставщика. Сервер передаёт только разрешённые агрегированные факты/коды предупреждений; модель выбирает ссылки на существующие факты/предупреждения. Пользователь видит соответствующие проверенные русские формулировки и происхождение NVIDIA. Новые количества, срочность, поставщики, утверждения или числовые заявления модели не применяются.
- Обе функции входят в демонстрационную приёмку, но отказ любого провайдера не блокирует детерминированный расчёт и не меняет числовой результат. До проверки реального вызова статус live-интеграции остаётся pending.
- До согласования передачи реальных данных внешние проверки используют только синтетические примеры. Ни клиентские ID, ни книги, ни подписанные ссылки, ни секреты не передаются модели/браузеру/логам.
- Ключи, точные модели и endpoint задаются серверной конфигурацией после проверки документации и доступа. Ограничиваются время, размер партии, токены и повторы; учитывается usage. По $50 — верхняя граница, а не цель расхода. Без проверенного тарифа не заявлять точный долларовый budget enforcement.
- B владеет `lib/ai/**` и тестами `tests/ai/**`. A подключает готовые адаптеры к своим задачам/репозиториям; B не меняет оркестратор и БД A. До передачи A контрактов допустимы отдельные тестируемые адаптеры, но не фиктивная серверная интеграция.

Критерии: полезный результат обоих API на синтетике, отклонение чужих/придуманных ссылок, ограниченный тайм-аут и контролируемый отказ, неизменность исходных количеств, явное отображение происхождения и резервного результата. Реальный вызов и моки фиксируются раздельно в итоговом отчёте.
