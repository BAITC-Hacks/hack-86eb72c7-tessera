# 13 — Подключение рабочего места к данным и расчётам

## Цель

Заменить демонстрационные адаптеры экрана 12 реальными контрактами, не переписывая математику или API. Пользователь проходит вход, импорт и запуск, видит собственные рекомендации/историю и состояние агентов. Утверждение подключается отдельно в 14a.

## Зависимости

06, 09, 09a, 10, 11, 12. Для внешних аккаунтов нужны настроенные тестовые окружения; при недоступности записать непроверенные шаги, не имитировать успех.

## Реализация

1. Серверная страница `/workspace` проверяет Clerk; макет12 превращается в защищённую реальную страницу. Активный проект — `/workspace?projectId=...`; чужой ID возвращает безопасный отказ, не переключает на чужие данные. Без проекта — русское пустое состояние/создание. После входа направлять сюда; в `app/layout.tsx` установить `lang="ru"` и русские metadata, сохранив тему.
2. `lib/client/procurement-api.ts` и узкие hooks: проверка ответа `{data}`, русские ошибки, отмена устаревших запросов. Проекты читаются/создаются через06; смена проекта сначала предлагает сохранить/отменить переход/отказаться от несохранённых правок (сохранение после14a), затем очищает результаты/подписки/локальные правки предыдущего. Выход из аккаунта очищает их сразу ради изоляции.
3. Загрузка: запрос S3 upload06 → загрузка → finalize09a → опрос статуса импорта → отчёт качества → выбор готовой DatasetVersion. Показывать версии, источники, отсутствие клиентских ID/stockout/lead time. Добавить экран предварительного сопоставления по двухэтапному контракту06/09a: первый finalize с нерешённым mapping получает needs_mapping и GET отчёта с листами/заголовками; исправление POST /imports/[importId]/attempts создаёт новую попытку на тех же SourceObject. Экран включает: выбор роли файла/листа, отображение найденных колонок, явное подтверждение готового профиля IEK/Systeme, исправление сопоставления разрешённых полей/единиц и повторная попытка с новым manifestHash. Не угадывать неизвестную бизнес-семантику; unresolved блокирует подтверждение. До согласования профиля на реальных файлах доступен только явно синтетический профиль. Нельзя показывать `ready` до принятия данных.
4. Подтверждённые параметры и scope проходят схему07/08. POST запуска09 использует стабильный ключ при сетевом повторе; новый намеренный запуск — новый ключ. Двойной клик не создаёт второй расчёт.
5. История проекта читается через `GET /api/projects/[projectId]/runs` (контракт09). Текущий результат — `GET /api/runs/[runId]` и `GET /api/runs/[runId]/recommendations?cursor=...&supplierId=...`. Не загружать все строки архива в браузер; сортировка/фильтры согласованы с серверной пагинацией.
6. Статусы11 обновляют ссылку на состояние, данные перечитываются из БД. Отмена09 и повтор после ошибки явно различаются. Refresh/reconnect восстанавливает выбранный запуск; хранить `runId` в URL наряду с `projectId`, проверять связь сервером.
7. Рекомендованное количество и evidence отображаются без клиентского пересчёта. Десятичные строки форматировать для `ru-RU` без изменения точного значения. ИИ-объяснение показывается с маркировкой/резервным вариантом, не как новое число.
8. До14a кнопки сохранения/утверждения/выгрузки в реальном режиме отключены с пояснением «Проверка и утверждение ещё не подключены». Демонстрационный экран не выдаёт локальное действие за сохранённое сервером. Не оставлять mock-успех на реальном проекте.

## Ограничения

Не менять правила расчёта, создавать новые серверные маршруты вместо контрактов или передавать секреты браузеру. Не подключать UI напрямую к Trigger/OpenAI. Не давать комнате Liveblocks права на утверждение.

## Проверка готовности

- [ ] В тестовой среде пройден путь вход → проект → импорт синтетики → расчёт → таблица/обоснование.
- [ ] Refresh, смена проекта, выход, поздний ответ и reconnect не смешивают данные разных проектов/пользователей.
- [ ] Ошибка XLSX, неполный набор, отказ API/модели/realtime, cancel и повтор представлены честно.
- [ ] Нет дублирования запусков при двойном клике/сетевом повторе; числовые значения совпадают с БД.
- [ ] Весь UI, включая Clerk/ошибки/доступные имена и metadata, русский.
- [ ] UI/API-тесты, `npm run lint`, `npx tsc --noEmit`, `npm run build` проходят; реальные проверки провайдеров отмечены отдельно.
