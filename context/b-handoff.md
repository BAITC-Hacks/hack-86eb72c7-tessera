# Передача B → A и проверка после объединения

Рабочая ветка B: `01-agent`; исходная общая точка `508de19`. Пользователь планирует объединить ветки в последний час. До объединения проверки адаптеров на имитациях не доказывают сквозную интеграцию. Ключи предоставляются позже.

## Доступ и общий API (03)

Версии03: `@clerk/nextjs 7.9.4`, `@clerk/localizations 4.17.1`. Проверки: `node --test tests/auth/*.test.mjs` (3/3), `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack` прошли. Стандартный Turbopack build ограничен окружением (создание процесса/порта); live Clerk ждёт ключи. HTTP без ключей проверен: экран входа200 с состоянием недоступности, API503 JSON. Это не доказательство настроенной сессии.

Код B предоставляет `requireUserId(): Promise<string>` и `authErrorResponse(error): Response` из `lib/server/auth.ts`. Отсутствие подтверждённой сессии: `401 UNAUTHENTICATED`; отсутствие конфигурации: `503 AUTH_UNAVAILABLE`. ID из запроса не используется. `requireSameOrigin(request)` нужен перед пользовательской cookie-мутацией: чужой/отсутствующий Origin — `403 INVALID_ORIGIN`. Неожиданные ошибки не превращаются в успешный ответ.

`apiData(data, init?)` и `apiError(status, code, message, requestId?, details?)` из `lib/contracts/api.ts` создают `{data}` и `{error:{code,message,requestId,details?}}`, с `Cache-Control: no-store`. В details передавать только безопасные данные валидации. Каждый обработчик A отдельно проверяет владельца ресурса; Proxy не выполняет эту проверку.

`lib/server/auth-policy.ts` — чистый внутренний помощник B для правил идентификации/Origin и их тестов; не сервис владения A. `.env.example` содержит только пустые ключи и локальные пути. На этапе03 переход после входа временно `/`; подключение защищённого `/workspace` относится к13.

## Демонстрационное рабочее место (12)

`/workspace` пока показывает только явно обозначенные синтетические данные. Два проекта, история, состояния импорта/расчёта, таблицы поставщиков, точные десятичные правки с причиной, явное подтверждение и предпросмотр работают локально. Это не защищённая реальная страница13 и не серверный экспорт14a. Изменение scope отменяет актуальность утверждения, показанные строки привязаны к scope исходного запуска.

Проверены4 теста состояния, lint, TypeScript, Webpack build и браузерные сценарии на320/768/1440px. Детали приёмки и ограничения — в трекере. Продолжать интеграцию через контрактные адаптеры, сохраняя отдельные рекомендованное и проверенное количества.

## Решения пользователя поверх исходного плана

- Интерфейс светлый и минималистичный; использовать `:root` токены, русский язык, компактные формы/таблицы, отдельные рекомендованные и проверенные количества.
- OpenAI и NVIDIA обязательны как полезные функции; при недоступных ключах live-проверки pending, синтетика отдельно.
- Детерминированное ядро, БД, API проектов/запусков, Trigger-оркестратор и серверное утверждение меняет A. B не создаёт их копии ради временной работы интерфейса.

Этот файл описывает передаваемую границу, а не подтверждение готовности. Фактические проверки и ограничения фиксируются в `progress-tracker.md` и итоговом отчёте.
